Just to quickly make sure we are all up to speed here, you can run shell commands from Vim via `:!...` and then read the output. Super powerful, super neat, glad we got that out of the way.

One of my very few faults is my goldfish-like memory. Sometimes I will run a quick script, and then before I have used the output, will have completely forgotten what it was. It's embarrassing.

> **Note:** Yes, I am aware I can use `:r !...`, but that's not always what I need, *okay*?

I'm not the first one to run into this problem apparently, which is why we are graced with `g<`.

`g<` brings up a preview of the output of your most recent command into the
pager. This view is a default pager view that lets you jump around like you
would in `less`, but it doesn't have any Vim-like personality. Since it is read-only output,
it means that there is a possibility that we will need to run `g<` twice (or more...)
when we are trying to copy some section of the output into our buffer.

So it is kinda buns if you aren't using something like tmux which allows you to *yoink* from your terminal. But, thankfully there is an alternative pager: The Wonderful, The Experimental, `ui2`.

> **Note:** I am also aware that `y` is for *Yank* not *Yoink*, but *yoinking* is a lot more fun, and you can't stop me from saying it or trying to get others to.

You can copy the default conf from the manual `:h ui2` into your init file (shown below), and then like magic, you have a not sucky pager for messages and command outputs. You can interact with it like a regular ol' buffer, and *yoink* from it to your heart's content!
```
    require('vim._core.ui2').enable({
      enable = true,
)}
```

### Example Time

Imagine you need a commit SHA (pronounce it *Shaw*, and don't let anyone tell you
otherwise) from your log, and aren't using the wonderful
[vim-fugitive](https://github.com/tpope/vim-fugitive). What are you to do?
Well, now it is as easy as running `!git log --oneline` (which should really be
`--one-line`), and then after the window with your command output appears, hit
`<CR>` again. Like any other window, `:q` will take you out of it, and unlike
any other window, it can be reopened with `g<`. I will omit how to copy
your commit SHA from that buffer out of the respect that I have for you.
